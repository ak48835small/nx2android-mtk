# 2026-11-10 — 联发科 Mali（Arm GPU）适配

## 做了什么

仓库是快照（无 .git、无 tools/、无 NDK、无已连接设备）。适配在“无 Mali 实机”前提下按能力探测实现，Adreno 路径未被改动行为。

宿主层（nxnative/dm/android/）：
- `gfx_vk.h`：`vkdev_t` 增 `family`(GF_ADRENO/GF_MALI/GF_PVR/GF_NVIDIA)、`lim_samplers/lim_sampled/lim_storage_img/lim_samplers_set/lim_images_set`、`has_border_nofmt`；`vkimg_t` 增 `dec_bytes`。
- `gfx_vk_core.c`：启动打印 GPU 家族 + 每 stage/每 set 的描述符上限 + 分配数；启动时逐项检查 replay 依赖的 10 个格式（RGBA8/R8/R8G8/RGBA16F/RGB10A2/RG11B10F/RGB9E5/RGBA4/D24S8/R32Uint storage），缺失打一行 `[RED]`；`has_border_nofmt = customBorderColors && customBorderColorWithoutFormat`。
- `gfx_vk_tex.c`：新增 `vk_fmt_linear()`（每格式查一次 FILTER_LINEAR，静态数组无锁缓存）；BC 解码统计 `g_bc_dec_*` + 预算回收 `bc_trim()`（`DM_VK_BC_MAX_MB`，无 BC 默认 2048MB，0=无限；只回收 packaged 且 GPU 未写、最近 4 帧未用的解码图，LRU 排序）；`vk_fmt` 对“任何 tiling 都不支持”的格式打 `[RED]`；`make_sampler` 在缺 `customBorderColorWithoutFormat`（Mali）时退回 transparent black 并记录；画进 CPU 解码 BC 纹理时一次性 `[RED]`。
- `gfx_vk_exec.c`：无线性过滤的浮点格式改绑 nearest 采样器（`g_tvc[].nl`），与整数视图同路。
- `gfx_vk_shader.c`：`shader_layout()` 超 per-stage 上限时打印实际数量与设备上限。

porter 层：
- 新增 `porter/gpu.py`（family / bc_textures / needs_cpu_decode / notes）。
- `porter/adb.py`：`bc_textures()` 改为委托 gpu.py，新增 `gpu_family()`、`ram_bytes()`（/proc/meminfo）。
- `porter/install.py`：Mali 不再抛 BuildError，改为安装前说明（CPU 解码、内存、<6GB 红字警告）。
- `tests/test_porter.py`：`GpuCapabilities` 5 个用例。

文档：新增 `docs/MALI.md`（现状/能力表/日志样例/天玑验证步骤/未完成项）；更新 `README.md`、`docs/ARCHITECTURE.md`（requires 语义）、`packaging/INSTALL.md`、`android_profile.py` 注释。

## 当天晚些时候：真机（Redmi K50 / 天玑 8100 / Mali-G610 MC6）跑通 Blasphemous 2

设备：`22041211AC`（rubens，mt6895），Android 13，11.7GB RAM，屏幕 1440x3200 @120Hz（display timing 报 8.25ms）。工具链在 `%APPDATA%\nx2android\toolchains`（ndk r27c / dotnet / platform-tools），prod.keys 在 `C:\Users\FIREBAT\Downloads\prod.keys`。

**决定性修复（zero-copy 的 fd 选择）**：MTK gralloc 给 AHardwareBuffer 句柄带了 **3 个 fd**，fd0 mmap 返回 EPERM、fd2 EINVAL、**fd1 才是能映射的 dma-buf**。原代码只试 fd0 → 所有内存池退化为“拷贝”，而拷贝池会让 `mtl_sub_begin` 每次都等 GPU 跑完前一次提交 → 帧时间 **600ms、GPU 仅 1-10ms、2 FPS、画面全黑**。改成遍历所有 fd 后：全部 zero-copy，帧时间 17-20ms，30-40 FPS，标题/菜单/新游戏正常。
（`gfx_vk_core.c pool_zero_copy` 现在带 -2..-8 分步错误码 + 每个 fd 的 mmap 结果，成功时只打一行 "the buffer's dma-buf is fd N of M"。）

**该设备的能力实测**：Vulkan 1.1.177 / driver 32.1.0；**没有** dynamic rendering、robustness2、depth clip control、display timing；有 timeline semaphore、ASTC、几何着色器、transform feedback、custom border colour；**per-stage 描述符上限是 500000（Valhall 根本不是瓶颈，之前文档里“Mali 16 个”的说法对 G610 不成立，已改文档）**。

**仍存在的问题**：开场过场动画的**视频画面全黑**（字幕正常），解码是好的（MediaCodec 输出 3110400 字节 NV12）。期间出现一次 `[RED] nvnBlendStateSetAdvancedMode 25`（未实现的 advanced blend），是下一个要查的点。

**调试手法**：debug 构建支持 `DM_CTL=<file>`（`host/hle_hid.c`），往该文件 append `A` / `Left` / `shot /path.png` / `env K=V` 即可遥控；`DM_KEYS=18:A,22:A` 是按时间脚本；`adb` 里 `/sdcard/...` 需要 `MSYS_NO_PATHCONV=1`。porter 在沙箱下跑会被 safe-delete 拦（tmp 目录几千个文件），要 `dangerouslyDisableSandbox`；`-o` 指到新目录可避开旧 data 的删除。

## CPU 优化（同日晚，用户点名 replay 的 CPU 成本）

`DM_VK_PROF=1`（进程级 1ms ITIMER_PROF 采样，输出库内偏移）+ `llvm-addr2line -e host-debug/libdmhost.so` 符号化（**注意：磁盘上的 .so 必须是当前安装的那次构建，否则地址全对不上**）。菜单场景 1161 样本的热点：

- 12% `dm_thread_enter`（guest→host gate，entry.S）
- 5.7% `thread_state_char`（`darwin_compat.c`，每次抢占判断读 `/proc/self/task/<tid>/stat`）
- 4.7% `pool_copy_back`（零拷贝池销毁时整池 16MB 拷回；MTK 的 dma-buf 是 uncached，约 160ms/池）
- 3.1% `img_new`（淘汰后重建图像）

改动：
1. `darwin_compat.c thread_state_char` 加 1ms 缓存 → **菜单 30fps（p50 29-33ms）→ 40fps（p50 16.9ms，64 帧 0 迟到）**。
2. `gfx_vk_core.c pool_copy_back` 由“malloc+memcpy 再 memcpy 回来”改为一次拷贝 + `mremap(MREMAP_FIXED)` 就位（省一半 uncached 读）。

游戏内（洞穴场景）仍是 30fps：**GPU 27ms/帧**是墙（60fps 需 16.6ms），CPU 优化只在 CPU-bound 的场景（菜单）体现。要继续提升必须动 GPU：per-game 减少 pass 或降内部渲染分辨率。
